# アプリ共通GitHub自動バックアップ基盤(app-sync)設計書

日付: 2026-08-10
ステータス: 承認済み

## 目的

個人用PWA群(カロリー計算アプリを最初の適用例とする)の記録データを、
1日1回自動でGitHubに保存し、PCにも自動同期する共通基盤を作る。
機種変更・紛失時にデータを復元でき、アプリが増えても設定作業が増えないことを目指す。

## 背景と決定事項

- 記録データは各アプリが端末のIndexedDBに保存しており、端末の紛失・故障で失われる
- 手動バックアップは(アプリが増えるほど)非現実的、というユーザー判断
- カロリー記録程度のデータに「外部通信なし」の厳格さは求めない(機密度に応じた判断)
- **保存タイミング**: アプリを開いたとき、その日まだ保存していなければ自動保存
  (PWAは閉じている間コードを実行できないため「毎日定刻」は不可能。
  使わない日はデータも変わらないので実害なし)
- **リポジトリ構成**: 全アプリ共通の1リポジトリ(アプリごとにフォルダ分け)
- **配布方式**: 中央ホスト型。共有モジュールを公開リポジトリのGitHub Pagesで配信し、
  全アプリが同一オリジンからimportする(案Aとして承認済み)
- **PC側同期**: 本フェーズに含める(日次自動pullタスクを1つ登録)

## 全体構成

リポジトリを2つ新設する。

| リポジトリ | 公開設定 | 役割 |
|---|---|---|
| `app-data` | 非公開 | 全アプリのバックアップデータ置き場。アプリごとにフォルダ(`calorie-app/backup.json` など) |
| `app-sync` | 公開 | 共有モジュール `v1/sync.js` をGitHub Pagesで配信 |

- バックアップは1日1回**上書き**保存。過去の履歴はgitのコミット履歴が自動的に保持する
  (日付ごとのファイルは作らない)
- 認証はfine-grained PAT 1つ(対象リポジトリ=`app-data`のみ、権限=Contents: Read and write)
- 全アプリがGitHub Pagesの同一オリジン(`taka070600538-tech.github.io`)配下にあるため
  localStorageが共有される。**PATはどれか1つのアプリで入力すれば全アプリに効く**

## 共有モジュール `sync.js` のAPI

ESMモジュール。公開URL: `https://taka070600538-tech.github.io/app-sync/v1/sync.js`

```js
initDailyBackup({
  appId: 'calorie-app',
  collect: async () => ({ ... }),   // アプリの全データをオブジェクトで返す
  restore: async (data) => { ... }, // オブジェクトをIndexedDBに書き戻す
});
```

### 動作

- **起動時チェック**: `localStorage` の `app-sync:lastBackup:<appId>` が今日の日付でなければ、
  `collect()` の結果をGitHub Contents APIで `app-data` の `<appId>/backup.json` にPUTし、
  成功したら最終保存日を今日に更新する
- **設定UI**: `renderSyncSettings(container)` で以下を各アプリの設定画面に埋め込める:
  - PAT入力欄(localStorageの共通キーに保存)
  - 最終保存日時と状態の表示
  - 「今すぐ保存」ボタン
  - 「GitHubから復元」ボタン
- **復元**: GETで `<appId>/backup.json` を取得し `restore(data)` に渡す。
  既存データがある場合は上書き確認を出す
- **Contents APIの手順**: GETで既存ファイルのshaを確認 → PUTにshaを含めて上書き。
  日本語を含むJSONのbase64化は `TextEncoder` → バイト列 → `btoa`(`btoa`直がけはUTF-8で壊れる)

### 読み込み方式(アプリ側)

- **動的import + 失敗時スキップ**。トップレベルimportにはしない
- オフラインや `app-sync` 配信障害のときもアプリ本体は普通に起動し、
  その回の保存がスキップされるだけ(次回オンライン起動時に再試行される)
- 各アプリの `sw.js` では `sync.js` をキャッシュ**しない**(オフライン時はどのみち
  保存・復元ができないため、キャッシュする意味がなく、更新が届かない問題も避けられる)

## カロリー計算アプリへの組み込み(最初の適用例)

- `collect`: `foods` / `meals` / `goals` の全レコード →
  `{ version: 1, exportedAt: <ISO8601>, foods, meals, goals }`
- `restore`: 全ストアをクリアしてから書き戻す
- 設定タブに「バックアップ」セクションを追加し `renderSyncSettings` を埋め込む
- `js/app.js` 起動時に `initDailyBackup` を呼ぶ(動的import、失敗時は何もしない)
- `sw.js` は変更なし

## PC側同期

- `app-data` を `D:\Obsidian Vault for Claude Code\Git\app-data` にclone
- タスクスケジューラに **`AppDataGitPull`** を1つ登録:
  - 毎日定時に `git pull`
  - `StartWhenAvailable` 付き(スリープで逃しても次回起動時に追いつく)
  - 成功/失敗をログファイルに追記
  - スクリプトはBOM付きUTF-8で保存(Windows PowerShell 5.1の日本語パス問題対策)
- 今後アプリが増えてもこのタスクはそのまま(リポジトリが同じため)
- Obsidianへの整理・転記は行わない(バックアップJSONのまま置く。必要になったら別途)

## エラー処理・制約

- **PAT未設定**: 保存を静かにスキップし、設定画面に案内を表示
- **通信失敗**: 静かにスキップ(次回開いたとき再試行)。設定画面で最終保存日時が
  古いままなのを確認できる
- **書き込み競合(sha不一致、422/409)**: shaを再取得して1回だけリトライ
- **復元時に既存データあり**: 上書き確認ダイアログを出す
- **端末は1台運用が前提**: 複数端末で同時に書くと後勝ち上書き。マージはしない
- **PATの有効期限**(最長1年): 切れたら設定画面で再入力

## テスト

- `sync.js` の純粋ロジックをnode:testでテストする:
  - 日次判定(最終保存日と今日の比較)
  - UTF-8対応base64エンコード/デコードの往復
  - バックアップペイロードの組み立て
- カロリーアプリ側: `collect` → `restore` の往復で元データと一致することをテスト
- ブラウザでの実機確認: 保存→`app-data`リポジトリにコミットが増える、
  IndexedDBを消して復元→データが戻る

## やらないこと(YAGNI)

- 複数端末間のマージ・双方向同期
- 記録ごとの即時保存
- 暗号化(GitHubの非公開リポジトリの保護に任せる)
- voice-diary-app / call-recording-app の本基盤への移行(現行のまま動いているものは触らない)
- Obsidianへの自動転記
